# 02: 多篇批量转换

**What to build:** 一次传入多个 PDF，逐篇在**各自所在目录**生成 `<文件名>_md/`。可用 `--out` 指定统一输出根，覆盖"各自目录"的默认行为。用户未指定存储位置时先提醒/确认。目标目录已存在时默认报错退出（防误删），只有 `--force` 才覆盖。终端一次传多个文件即可完成，全程不经 AI。

**Blocked by:** 01.

**Status:** ready-for-agent

- [x] 未指定存储位置时先提醒/确认
- [x] 目标已存在且未 `--force` 时报错退出

## Comments

- 2026-10-01: 实现完成。`scripts/pdf_extract.py` 的 CLI 改为 `pdf` 多值 + `--out`；新增 `tests/test_batch.py`。全套 37 个测试通过（含 `PDF_EXTRACT_E2E=1` 真实 MinerU）。
- 定位：默认每篇 `<pdf目录>/<name>_md/`；`--out ROOT` 时统一为 `<ROOT>/<name>_md/`。批量未给 `--out` 时 stdout 打印提醒 `no --out given; writing <name>_md/ next to each PDF`。
- 交互式「确认」按规格 D8 由 AI/skill 负责（工单 05）；终端路径保持非交互、可脚本化，因此脚本只提醒不阻塞。
- 存在目标时在**任何转换前**汇总报错并退出码 1；`--force` 先删除再写。
- 额外健壮性（低成本，防静默覆盖）：`--out` 下重名 stem 直接报错退出 1；批量逐篇继续，某篇失败不拖垮其他，退出码取首个失败码。
- 真实冒烟：两篇论文批量、无 `--out` 与 `--out` 两种模式产物正确，临时目录无残留，重复运行触发存在性守卫退出 1。
