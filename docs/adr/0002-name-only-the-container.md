# ADR-0002：只命名容器；内部固定 `cleaned.md` + `image/`

- 状态：接受
- 日期：2026-10-02
- 相关：`scripts/pdf_extract.py`（`_plan_targets()`、`convert()`）、`SKILL.md`

## 背景

产物要落在用户指定位置，batch 时多个 PDF 可能写到同一个目录。如果**容器名和内部
文件名都随 PDF 变化**，消费方（AI / 用户 / 下游脚本）就得处理多种内部命名，且两个
PDF 可能互相覆盖。

## 决策

**只让容器名可变**：`<container>_md/`，`<container>` 默认是 PDF 文件名 stem，
`--name` 可覆盖。

**容器内部名字固定**：`cleaned.md` + `image/`，图片用**相对**链接 `![](image/...)`。
容器名冲突时按输入顺序加 `_1` / `_2` 后缀，保证 batch 不自覆盖。

## 后果

- 消费方只需处理**一种**内部布局；容器提供隔离。
- `--name` 语义简单：只管容器，不管里面。
- 代价：用户无法自定义内部文件名（目前也不需要）。

## 考虑过的替代方案

- **内部文件也跟随 PDF 命名**：消费方要适配多种布局，已否决。
- **用 UUID / 内容哈希命名容器**：不可读、不可预期，已否决。
- **batch 共享一个容器**：多 PDF 会碰撞，且无法用一次 `--name` 表达，已否决。
