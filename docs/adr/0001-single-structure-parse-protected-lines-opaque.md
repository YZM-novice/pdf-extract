# ADR-0001：`clean()` 只做一次结构解析；protected 行对所有规则不透明

- 状态：接受
- 日期：2026-10-02
- 相关：`scripts/pdf_extract.py`（`clean()`、`_analyze_structure()`、`_Structure`）

## 背景

早期每条清洗规则各自扫描 markdown、各自推断"哪里是 front matter / 参考文献 /
代码围栏"。这带来两个问题：

1. **重复且易不一致**：结构判断散落在各规则里，新增规则要重新实现一遍。
2. **围栏/`<details>` 被误删**：代码块或折叠块里的行可能命中样板规则而被删掉。

## 决策

`clean()` 在开头**只调用一次** `_analyze_structure()`，得到 `_Structure`
（`title_line` / `references_line` / `protected`），**所有规则共享**这份结构。

`protected` 行（代码围栏内、`<details>` 内）对**结构解析和所有规则一律不透明**：
重建输出时在一个地方统一把它们从待删集合中过滤掉，规则**不再自行**跟踪围栏或
`<details>`。

## 后果

- 新增规则只需读 `_Structure`，不必重新推断结构，也不必修围栏逻辑。
- 结构锚点缺失时对应字段为 `None`，该区域**原样保留**（fail-safe）。
- 代价：protected 行**永不**被清洗，即使其中确实有样板。

## 考虑过的替代方案

- **每条规则自行判断 protected**：重复、易漏，已否决。
- **不保护围栏/`<details>`**：会删掉用户代码块，不可接受。
- **多次解析、按规则需要局部重解析**：这正是重构前的状态，已否决。
